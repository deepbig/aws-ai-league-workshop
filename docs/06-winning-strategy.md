# 06. 1등 전략 — 점수 극대화 플레이북

> 전제: 세부 채점식은 [당일] 공개. 아래는 관찰된 메커니즘에서 도출한 **변하지 않는 우위 요소** 중심. 당일 채점식 확인 후 가중치만 재조정.

---

## 1. 점수 방정식 (작업가설)

```
Score ≈ Σ(수집 코인 가치) + Σ(격파 챌린지 점수) + 보너스[당일] − 페널티[당일]
        제약: 시간 예산 T, 생명 L
```

→ **세 가지 우위 레버**(채점식과 무관하게 거의 항상 점수↑):

1. **챌린지 정답률 → 100%에 수렴** (코드 실행)
2. **단위 시간당 코인 회수율 극대화** (예산 제약 경로 최적화)
3. **생명·시간 낭비 0** (무의미 전투/이동 제거)

---

## 2. 레버 1 — 챌린지: "절대 암산하지 않는다" ★최우선

관찰 예시는 *"1000–1100 연속 소수 최대 gap"*. LLM 암산은 오답 확률이 유의미하게 존재 → **오답 = 생명/점수 손실**. 반면 5줄 파이썬이면 100% 정답.

원칙:
- 모든 챌린지는 **Code Interpreter / Lambda로 계산 후** 답을 낸다. LLM은 "문제 → 코드 변환 → 실행 → 답 추출"만.
- 답안은 **Guardrails로 포맷 고정** (예: 숫자만, 공백/설명 금지).
- 자주 나올 유형 대비 스니펫을 사전 준비(부록 A): 소수/약수/조합·확률/수열·점화식/그래프·경로/문자열·파싱/모듈러 산술.
- 같은 유형 재출제 대비 → 푼 문제 유형·해법을 **Memory에 캐싱**.

> 이 한 가지만 제대로 해도 다수 참가자(LLM 암산 의존) 대비 구조적 우위.

## 3. 레버 2 — 경로: "전수집"을 예산 문제로 푼다 ★시뮬레이션으로 규명 완료

목표가 *"모든 코인 수집 + 보물"* → 단순 최단경로 아님. **제한 시간 내 가치 합 최대화** (Orienteering / 예산제약 TSP).

**실측 결론** ([docs/08-routing-findings.md](08-routing-findings.md)): 진짜 최적해(Held-Karp DP, N≤18) 대비
- `greedy+LS`(탐욕+2-opt+or-opt+삽입): **~99.8% 최적, 15ms급** → 실전 in-agent Navigator
- `ILS`/`BEST 앙상블`: **99.8~100% 최적** → 초기/여유 시 정밀 경로
- 단순 그리디 대비 FULL 규모 **약 +17%**. 라우팅 추가 개선 여지 < 0.2% = 사실상 해결.

전략:
- Navigator를 **결정론적 Lambda 알고리즘**으로 구현(LLM 경로추정 금지 — 부정확).
  검증된 구현: `sim/planners.py`의 `plan_greedy_ls`(실시간) / `plan_ils`(정밀).
- 절차: ① 맵 그래프화(BFS 거리행렬) ② 가치/비용비 탐욕 초기해 ③ 2-opt+or-opt로 비용 최소화 ④ 남은 예산에 미방문 노드 삽입 ⑤ (여유 시) double-bridge 교란 반복(ILS).
- "다음 N스텝 계획 → 실행 → 재계획" (receding horizon). greedy+LS는 매 턴 재계획해도 부담 없음.

## 4. 레버 3 — 시간·생명 = 예산 관리

- 매 결정 전 `남은시간`, `남은생명`으로 **리스크 게이트**: 위험 전투 회피, 저가치 원거리 코인 포기.
- 불필요한 도구 호출 최소화(안내자료도 "불필요한 도구 호출 줄이기" 명시 — 지연/비용↓).
- 종료 임박 시: 확정 가능한 점수만 회수, 모험 금지.

## 5. 레버 4 — Memory로 복리 효과

기록: `map_layout / collected / solved_challenges(유형·해법) / enemy_positions / treasure_clues`.
System Prompt에 **"행동 전 Memory 조회 → 행동 후 갱신"** 루프 강제 → 재탐색·재계산 0.

## 6. 레버 5 — 반복 개선 루프 (워크샵은 "개선" 대회)

안내자료: *"에이전트를 만들고 **개선하며** 점수를 높여가는"*. → 1회 완성도보다 **사이클 수 × 사이클당 개선폭**.

```
플레이 → 로그 수집 → 실패 유형 분류(경로/챌린지/시간/생명)
       → 가장 큰 손실원 1개만 수정 → 재플레이
```
- AI Assistant에 **로그 + 본 전략 + sim 결과**를 함께 투입해 개선안 도출.
- 한 번에 한 변수만 변경(무엇이 점수를 올렸는지 귀속 가능하게).

## 7. 당일 채점식 확인 시 조정 매트릭스 [당일]

| 당일 확인 사실 | 즉시 조정 |
|---|---|
| 챌린지 배점 ≫ 코인 | 챌린지 우선 라우팅, 전투 적극 유도 |
| 코인 가치 차등 존재 | Navigator 가치가중 경로로 전환 |
| 오답 페널티 큼 | 불확실 챌린지 회피 + 코드검산 2중화 |
| 시간 보너스 존재 | 조기 종료 가치 vs 추가 수집 트레이드오프 재계산 |
| 보너스 조건(연속 정답/특정 타일 등) | 보너스 트리거를 경로/정책에 1급 목표로 삽입 |
| 행동 인터페이스 = 자연어 | 출력 스키마·Guardrails 즉시 재정의 |

→ 이 표의 분기는 `sim/config.json`에 파라미터로 존재. 값만 바꿔 재시뮬레이션 후 채택.

## 부록 A. 챌린지 풀이 코드 패턴 (사전 암기/스니펫화)

```python
# 소수/소수 gap
import sympy
def max_prime_gap(lo, hi):
    ps = list(sympy.primerange(lo, hi+1))
    return max(b-a for a, b in zip(ps, ps[1:]))

# 조합/확률
from math import comb, perm, factorial, gcd
from itertools import permutations, combinations, product

# 수열/점화식 — 메모이즈
from functools import lru_cache
@lru_cache(None)
def f(n): return n if n < 2 else f(n-1)+f(n-2)

# 그래프 최단경로
import heapq
def dijkstra(adj, s):
    dist = {s: 0}; pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, 1e18): continue
        for v, w in adj[u]:
            if d+w < dist.get(v, 1e18):
                dist[v] = d+w; heapq.heappush(pq, (d+w, v))
    return dist
```

원칙: **문제 → 가장 단순한 정확 계산 코드 → 실행 → 검산(가능하면 2가지 방법) → 포맷된 답**.

## 부록 B. 프롬프트 템플릿 (초안 — 당일 규칙으로 미세조정)

**Supervisor (정책)**
```
역할: 미로 게임 마스터. 매 턴 [남은시간, 남은생명, 맵상태, 미해결챌린지]를 받아
다음 중 하나만 출력: MOVE <경로> | SOLVE <챌린지ID> | COLLECT | RETREAT.
규칙:
- 행동 전 Memory 조회, 행동 후 갱신.
- 챌린지는 절대 추측하지 말고 Challenge Solver에 위임.
- 경로는 Navigator 결과를 신뢰. 시간/생명 예산 초과 행동 금지.
- 기대 점수가 가장 높은 단일 행동만 선택. 설명 금지.
```

**Challenge Solver**
```
입력: 문제 텍스트. 절대 암산 금지.
절차: (1) 문제를 계산 가능한 형태로 정식화
      (2) Code Interpreter로 파이썬 실행해 정답 계산
      (3) 가능하면 다른 방법으로 검산
      (4) 규정 포맷으로 정답만 출력 (설명·단위·공백 금지)
```

**Navigator**
```
입력: 맵 그래프, 코인 위치/가치, 현재좌표, 남은시간.
출력: 예산 내 가치합 최대 경로 (좌표 시퀀스). LLM 추정 금지 — Lambda 알고리즘 결과만 반환.
```
