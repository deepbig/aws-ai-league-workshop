# 07. 시뮬레이션 계획

세부 채점식은 [당일] 공개되므로, **관찰된 메커니즘을 파라미터화한 로컬 시뮬레이터**로
전략을 사전 검증하고, 당일엔 `sim/config.json`의 값만 교체해 재검증한다.

## 목적

1. 그리드 미로 점수를 **가장 높이는 경로 방법**을 규명 → [docs/08-routing-findings.md](08-routing-findings.md).
2. "챌린지 코드풀이"가 점수에 주는 효과를 **정량 측정**.
3. 당일 채점식 변경 시 어떤 전략 분기가 우월한지 **즉시 재계산**.

## 구성 ([sim/](../sim/))

| 파일 | 역할 |
|---|---|
| `sim/config.json` | **모든 [당일]-미정 값**(맵·시간·생명·코인 가치·챌린지 배점·페널티·보너스) |
| `sim/game.py` | 그리드 미로 환경. 보상 노드/거리행렬 추출, 점수 평가. 시작점 연결성 보장 |
| `sim/planners.py` | 경로 플래너 7종 + **Held-Karp 진짜 최적해(`plan_exact`)** |
| `sim/bench.py` | **3단계 벤치마크**: SMALL/MID(최적해 대비 %opt) + FULL(장기 레퍼런스) |
| `sim/agent.py` | 강한 라우터 위에서 챌린지 코드풀이 vs 암산 레버 정량화 |
| `sim/run.py` | 빠른 요약(레버 A 라우팅 / 레버 B 코드풀이) |

## 검증 방법론 (정직성)

- **최적성 검증**: SMALL(N~11)·MID(N~18)에서 Held-Karp 비트마스크 DP로
  **진짜 최적해**를 계산해 각 플래너 `%opt` 측정. 추측이 아니라 증명된 상한 대비 비교.
- **FULL(N~28)**: 최적 계산 불가(2^28). 장기 ILS를 레퍼런스로 상대 우열 + 절대점수.
- 결과: ILS/BEST가 N≤18에서 **최적의 99.8~100%** → 라우팅은 사실상 해결.

## 실행

```bash
python3 sim/run.py            # 빠른 요약 (레버 A/B)
python3 sim/bench.py          # 3단계 정밀 벤치 (SMALL/MID/FULL, %opt)
python3 sim/bench.py 60       # seed 수 지정
```

## 당일 운영 루프

```
1. "극대화하는 방법/추가 규칙/챌린지·보너스/워크숍 스튜디오 문서" 정독
2. config.json에 실제 값 입력 (배점·페널티·보너스·시간·생명·코인 가치)
3. python3 sim/bench.py → 최고 점수 플래너/전략 분기 확인
4. plan_greedy_ls(실시간) / plan_ils(정밀) 로직을 AgentCore Navigator에 이식
5. 챌린지는 Code Interpreter로 100% 정답 처리
6. 실플레이 로그 → 실패유형 분류 → 한 변수만 수정 → 반복
```

## 한계 (정직하게)

- 행동 인터페이스·챌린지 출제 규칙·맵 공개 방식은 [추론]. 시뮬레이터는
  *전략 우선순위·라우팅 알고리즘 판단용*이지 실점수 예측기가 아님.
- 단, **경로 최적화 결론(강한 Orienteering 솔버가 최적에 근접)**은 채점식이 바뀌어도
  견고. 당일 [확정]값으로 `config.json` 갱신 시 신뢰도 급상승.
