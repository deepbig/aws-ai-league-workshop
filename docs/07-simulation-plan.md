# 07. 시뮬레이션 계획

세부 채점식은 [당일] 공개되므로, **관찰된 메커니즘을 파라미터화한 로컬 시뮬레이터**로 전략을 사전 검증하고, 당일엔 `sim/config.json`의 값만 교체해 재검증한다.

## 목적

1. "챌린지 코드풀이"·"예산제약 경로"가 점수에 주는 효과를 **정량 측정**(ablation).
2. 당일 채점식 변경 시 어떤 전략 분기가 우월한지 **즉시 재계산**.
3. 프롬프트/정책 변경을 실기 전에 빠르게 거르기.

## 구성 ([sim/](../sim/))

| 파일 | 역할 |
|---|---|
| `sim/config.json` | **모든 [당일]-미정 값**(맵 크기·시간·생명·코인 가치·챌린지 배점·페널티·보너스) |
| `sim/game.py` | 그리드 미로 게임 환경 (관찰된 메커니즘 구현) |
| `sim/agent.py` | 베이스라인 에이전트 + 전략 토글(코드풀이/예산경로/메모리) |
| `sim/run.py` | N 에피소드 실행, 점수 분포·ablation 리포트 |
| `sim/README.md` | 실행법 |

## 모델링한 메커니즘 (관찰 기반)

- 그리드 미로, 코인(가치), 적, 보물, 생명 L, 카운트다운 T.
- 적 조우 → 챌린지 출제. 정답 → 격파/점수, 오답 → 생명/페널티.
- 점수 = 코인 + 챌린지 + 보너스 − 페널티 (가중치 전부 config).

## 검증 시나리오 (ablation)

| 시나리오 | 토글 | 기대 |
|---|---|---|
| Baseline | 탐욕 이동 + LLM 암산(오답률 p) | 하한선 |
| +코드풀이 | 챌린지 정답률→100% | 큰 폭 상승(레버1 입증) |
| +예산경로 | 시간내 가치합 최대 경로 | 코인 수집률 상승(레버2) |
| +메모리 | 재탐색/재계산 제거 | 시간 효율 상승(레버5) |
| Full | 전부 ON | 상한선 |

→ 각 레버의 **한계 기여도**를 수치로 확보 → 당일 우선순위 근거.

## 당일 운영 루프

```
1. "극대화하는 방법/추가 규칙/챌린지·보너스" 정독
2. config.json에 실제 값 입력 (배점·페널티·보너스·시간·생명)
3. python3 sim/run.py  → 어떤 전략 분기가 최고 점수인지 확인
4. 실제 AgentCore 에이전트에 해당 정책/프롬프트 반영
5. 실플레이 로그 → 실패유형 분류 → 한 변수만 수정 → 반복
```

## 한계 (정직하게)

- 행동 인터페이스·챌린지 출제 규칙·맵 공개 방식은 [추론]. 시뮬레이터는 *전략 우선순위 판단용*이지 실점수 예측기가 아님.
- 당일 [확정]값으로 config 갱신 시 신뢰도 급상승. 구조(레버 우선순위)는 채점식이 바뀌어도 대체로 견고.
