# Amazon Bedrock Guardrails 설정 (이 게임용)

> **Guardrails는 Supervisor에만 연결**(전용). 직접 생성·구성해야 함.
> 목적: 안정성(safety) 챌린지를 안전하게 처리 + 유해 출력 차단.
> ★ **그러나 과도하게 막으면 챌린지가 통째로 차단되어 점수를 잃는다** — 민감도 보정이 핵심.

## 생성 절차 (UI)

1. "Amazon Bedrock Guardrails" 아래 `+` 클릭 → Create Guardrail.
2. **이름** + **차단 시 반환 메시지**(blocked message) 입력.
   - blocked message는 짧고 안전하게(예: "I can't help with that request.").
3. 콘텐츠 필터 카테고리(증오/폭력/성적/모욕/불법행위/프롬프트 공격 등)를 규칙에 맞게 구성.
4. Next → Create Guardrail.
5. **Supervisor 에이전트에 연결**(Associate) → Save Changes.
6. Supervisor 옆에 guardrail이 보이면 성공.

## ★ 민감도 보정 (가장 중요 — 점수 직결)

게임 가이드 힌트:
- **"모든 챌린지가 차단되면 필터 민감도를 낮춰라."**
- **"규칙을 다시 읽어라 — Violent Violet이 무엇을 허용하는지 명시되어 있다."**

함의: 안정성 챌린지("Violent Violet")는 일정 수위의 내용을 **허용**하도록 설계돼 있다.
Guardrails가 너무 엄격하면 그 챌린지의 (자동 생성된, 수정 불가한) 입력 프롬프트나
에이전트의 정당한 답변이 차단되어 **그 챌린지를 못 푼다**.

설정 원칙:
- **민감도는 LOW~MEDIUM에서 시작**. 챌린지가 막히면 단계적으로 낮춘다.
- 규칙의 **Violent Violet 허용 범위를 읽고**, 그 범위 내 내용은 통과하도록 필터를 맞춘다.
- **과차단(over-block) > 과허용**의 손해가 크다(챌린지 0점 + 토큰 낭비). 안전 최소선만 유지.
- 입력 필터는 챌린지 프롬프트가 통과할 만큼 관대하게, 출력 필터는 진짜 유해 생성만 차단.

## 무엇을 막고 무엇을 허용하나

| 막아야(차단) | 허용해야(통과) |
|---|---|
| 명백히 유해한 출력 생성 | 안정성 챌린지의 정당한 질문/시나리오 |
| 프롬프트 인젝션·주제 이탈(게임 외) | 폭력/민감 주제를 *다루는* 안전한 답변 |
| 실격 유발 행동 유도 | Violent Violet이 명시적으로 허용하는 수위 |

→ 안정성 챌린지는 "유해 부분은 거절하되 안전하고 책임감 있게 답"하면 고득점.
   Guardrails는 이 답변을 막지 않도록(over-refusal 방지) 보정.

## 행동 유효성 (게임 규칙 강제 — 보조)

- 막힘(통과 불가) 셀 이동 차단 ★(강제 통과 시 게임 종료).
- 코드 미실행 상태의 수학 챌린지 답안 제출 차단(검증 플래그 필수).

## 운영 / 반복 개선

- 챌린지가 차단되면: **민감도 한 단계 ↓ → 재플레이**. 한 번에 한 카테고리만 조정.
- 차단 로그를 Memory `run_stats`에 적재 → 어떤 필터가 챌린지를 막는지 식별.
- 규칙 항목은 파라미터로 외부화 → 당일 값만 갱신, 정책 구조 불변.

## 실격(DQ) 경계 (Guardrails는 보조 수단)

- 실격 사유(도구 내 외부 모델, 프롬프트 정답 하드코딩, 범위 외 작업)는 **설계·코드 차원**에서
  방지. Guardrails는 범위 외/부적절 출력을 막아 보조할 뿐, DQ 방지의 1차 책임은 구현에 있음.
